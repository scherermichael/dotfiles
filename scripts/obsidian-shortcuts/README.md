# Vault inbox shortcuts

Apple Shortcuts that put something into the inbox of an Obsidian vault,
generated by `vault_shortcuts.py` and installed by `install.sh` on every
`restore.sh`.

| Shortcut | Vault | Mac | iPhone |
|---|---|---|---|
| Add to Vault Inbox (*Label*) | fixed | hotkey; right-click text → Services; menu bar | — |
| Add to Vault Inbox | asks | share menu | share sheet, home-screen icon |
| Add File to Vault Inbox | asks | Finder → Quick Actions / Services | share sheet, home-screen icon |

- **Hotkey shortcuts:** there is one for each vault present on the Mac. The first
  vault in the list gets ⌘⌥, and the second ⌘⌥⇧,. The dialog starts with the
  selected text, or empty.
- **The two picker shortcuts** offer the vaults whose inbox the device can reach.
  With only one, they skip the list.
- **Every entry is an inbox task:**
  `- [ ] text ➕ date`, with further lines indented.
  `- [ ] PDF - name ➕ date` or `- [ ] Image - name ➕ date`, with a link to the
  stored file below it.
  - PDFs and images stay as they are.
  - HEIC becomes JPEG, since Obsidian can't display HEIC.
  - Anything else, such as a web page shared on the phone, becomes a PDF, with
    the page's address on a line of its own below the link.
- **A due date is typed as `+N` at the end of the first line:** N days from
  today, with `+0` for today. `Angebot prüfen +3` becomes
  `- [ ] Angebot prüfen ➕ 2026-10-31 📅 2026-11-03`.
  - **Only counts after a space:** `+49 170 …` at the start of a line and `C++`
    stay text. A first line that really ends in something like `+3` would be
    read as a date.
  - **Why the shortcut adds one day per round:** "Adjust Date" ignores a
    number of days taken from a variable, however it is passed, and counts 0.
    So it adds a fixed 1 day, N times.
- **A web page shared to "Add to Vault Inbox"** becomes a bookmark:
  `- [ ] Web - <title>`, with the address indented below.
  - With text selected, Safari hands over only the text and no address, so the
    note then carries the text alone. Nothing a shortcut can change.
  - The address is read from the page's "Page URL" property. "Get URLs from
    Input" finds nothing in a web page.

```sh
scripts/obsidian-shortcuts/install.sh          # install or update, as restore.sh does
scripts/obsidian-shortcuts/install.sh status   # what would happen; changes nothing
scripts/obsidian-shortcuts/install.sh build --out /tmp/shortcuts   # readable plists
python3 scripts/obsidian-shortcuts/test_vault_shortcuts.py
```

## Where the vaults come from

`private/obsidian-vaults.sh`, from the arrays starting with `inboxVault`. The
public part knows no vault names or paths.

- **Order is priority:** a vault's position decides its hotkey. That's why the
  work Mac, with only the work vault, needs no setting of its own.
- **The inbox folder is listed there** rather than read from the vault's
  `.gtd.json`. The picker shortcuts contain every vault, and a Mac lacking one
  has to build them the same way. The installer warns if the two disagree.

## Why it works the way it does

Shortcuts gives a script very little to work with, and every rule below comes
from a limit found by trying.

- **No binary in the repo.** The shortcuts are built step by step in
  `vault_shortcuts.py`. Shortcuts stores variables inside text as UTF-16
  offsets, so template files with placeholders wouldn't survive a substitution.
- **Every import makes a new shortcut.** "Replace" in the import dialog keeps
  the old one, renamed "… 2", and the new one gets a new ID. A script can't
  delete shortcuts either: AppleScript's `delete` reports success and does
  nothing.
  - So the installer moves superseded copies into the folder **"Replaced (safe
    to delete)"**. Empty it by hand now and then.
- **Only outdated shortcuts are imported, and each import needs one click.**
  Every shortcut answers a fixed input token with its build ID, a hash of its
  definition. The installer runs each one with that token and compares.
  Shortcuts' own step count can't be used: it is 0 for every imported shortcut.
- **Only shortcuts in the folder "Vault Inbox" are asked.** Running a
  hand-made shortcut with the token would open its dialog, or append the token
  to an inbox. A shortcut of the same name outside that folder is replaced
  without being run.
- **Hotkeys live in the Services settings, keyed by the shortcut's ID**
  (`defaults read pbs NSServicesStatus`). After an import, the installer moves
  the key to the new ID, changing only those entries.
- **Whether Finder shows a Quick Action is stored there too,** not in the
  shortcut file (`presentation_modes`). An imported shortcut is therefore missing
  from Finder even though the file names Finder as a surface, and the editor
  shows the toggle off.
  - The installer switches it on for the file picker's current ID.
  - It relaunches Finder when that setting changed, since Finder reads its Quick
    Actions only at start. That happens only after the file picker was
    re-imported.
- **Links carry the name the shortcut chose, in composed form.** Obsidian
  matches links against file names in composed form ("ä" as one character).
  A decomposed link ("a" plus a combining diaeresis) never resolves; clicking
  it creates an empty note named after the link.
  - **Why it matters:** iOS hands the stored file's name back decomposed, and
    files that went through iOS or iCloud keep decomposed names. So the
    shortcut composes the name itself (`COMPOSABLE`) and never reads it back.
  - **A taken name** therefore gets date and time appended
    (`Invoice 2026-10-31 011241.pdf`). Shortcuts' own "-2" numbering would only
    show up in the name read back.
- **No "has any value" on a text that can come out empty.** Shortcuts counts
  an empty text as a value. Replace Text, Text and a property of the wrong
  kind of item (a web page's address on plain text) all return empty text,
  never nothing.
  - **What happened:** the check passed every time, and the next step failed
    or wrote nonsense.
  - **What the shortcuts do instead:** a pattern turns a hit into a fixed marker
    such as `⟦due⟧`, or a value is wrapped in `⟦…⟧`, and an "is" comparison
    against that decides.
  - **The test** `test_no_text_is_asked_whether_it_has_any_value` keeps it that
    way.
- **Every step carries an ID,** as in a shortcut made in the editor. Shortcuts
  remembers "Always Allow" per step. For a step without an ID it stored
  nothing and asked again on every run. The Privacy list in the shortcut's
  details shows none of this either way.
- **Parked copies keep the settings they had,** so they would show up next to
  the new one in Finder and the Services menu. The installer takes them out of
  every menu and off every key.
- **Addresses are a root plus a path, with no IDs.** A folder picked in the
  editor carries an iCloud domain ID belonging to the device it was picked on,
  and fails on all others. The roots:
  - **Obsidian's iCloud folder,** for the iCloud vault on Mac and iPhone alike.
    Not `~/Library/Mobile Documents` via the home folder: started from Spotlight
    or the share menu, a shortcut may not read there, and quietly finds nothing.
  - **The home folder,** for every other vault on the Mac.
  - **Obsidian's on-device storage,** for the other vaults on the iPhone.
- **A missing root stops the shortcut.** Below an existing root, a missing path
  comes back empty, which is what the vault check relies on.
  - So on a Mac without Obsidian's iCloud folder (the work Mac, whose iCloud is
    restricted), the picker leaves the iCloud vault out of its Mac check.
  - That makes its build differ from the other Macs'. This is harmless, because
    the work Mac has its own Shortcuts library.
  - Within one library, every Mac should have the folder, or the Macs would keep
    replacing each other's picker.

## What stays manual

- **One click per import,** in the dialog `restore.sh` opens. The installer
  waits three minutes per dialog, then moves on without parking anything or
  moving a hotkey.
  - **A click after that** still adds the shortcut, but outside the "Vault
    Inbox" folder. The installer never asks a shortcut there for its build,
    because it might be a hand-made one. So the next run imports again, and
    the late copy ends up parked.
- **Emptying "Replaced (safe to delete)"** in the Shortcuts app, soon after an
  install. On the Mac, parked copies are hidden from every menu. On the
  iPhone they stay in the share sheet, under the same name as the new copy,
  until they're deleted.
- **iPhone home-screen icons:** they refer to the shortcut's ID. After a picker
  shortcut was re-imported, add its icon again.
- **The other personal Macs:** they share the Shortcuts library through iCloud,
  so a re-import on one changes the IDs on all of them. Run `restore.sh` on the
  others, or just `install.sh`, to move their hotkeys along.
- **First run on a new Mac:** allow the terminal to control "Shortcuts Events"
  when macOS asks.
- **First use of a new copy:** Shortcuts asks whether the shortcut may append
  or save what it received from another app. Choose "Always Allow". It sticks
  for that copy, so a re-imported one asks once more, on Mac and iPhone alike.
  - The first run after that prompt may start over once. That can leave a
    second copy of a file, safe to delete.

## Known quirks

**A very long web page can stall "Add File to Vault Inbox" on the iPhone.**
A shortcut started from the share sheet runs with little memory, and "Make PDF"
of a page such as a news site's front page doesn't finish. The run sits there
with an empty progress notification and nothing stored. Closing Safari in the
app switcher ends it. A single article goes through; for a front page, the
bookmark note via "Add to Vault Inbox" is the way.

**Cancel with text selected brings the dialog back, empty.** A second Cancel
ends it.

- **The cause:** when a Services run that received the selection is cancelled,
  macOS runs the shortcut once more, without input.
- **When it happens:** with the hotkey and with the right-click menu alike. Not
  without a selection, and not on OK.
- **The fixes cost more than the quirk:** giving up the pre-filled selection, or
  a marker file that would have to be checked before every dialog.
